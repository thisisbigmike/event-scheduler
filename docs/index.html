Event Scheduling Management System

A web-based system that books events into IMT's venues without clashes, and tells every attendee by SMS and e-mail.

The problem it solves

When events are scheduled by hand, three things go wrong. The system tackles each one.

1

Venue clashes

Two events can be booked into the same hall at overlapping times. The system rejects any booking that overlaps another at the same venue.

2

Late or missed notices

Staff hear about events late or not at all. The system sends every attendee an SMS and an e-mail, and a reminder within the 24 hours before the event.

3

No records

There's no history of who was invited or how venues are used. The system keeps both, with feedback and printable reports.

How the venue clash check works

The check runs while the admin fills in the form, and again on the server when the event is saved, inside a transaction that locks the venue.

For the same venue on the same date, a new booking clashes when: existing start < new end
AND existing end > new start Cancelled events don't hold the venue, and an event being edited isn't compared with itself.

What it does

Two kinds of user: the administrator who schedules events, and the staff who attend them.

A

Staff registration

Staff register with an IMT staff ID, checked against the staff list, plus a passport photo. Accounts stay inactive until the admin activates them.

B

Event scheduling

The admin picks the venue, date, start and end time, and attendees. A clashing booking is never saved.

C

SMS and e-mail

After the admin answers a security question, attendees get an SMS through a Nigerian bulk SMS gateway, and an e-mail. Every message is logged.

D

Feedback and reports

Staff view their events and send feedback. Reports show venue usage, and each event's attendees and their feedback.

Try it

This page is static. The system itself needs PHP and MySQL, so run it one of these ways, then log in with a demo account.

GitHub Codespaces

Click Run it live and create the codespace. When the build finishes, open the Ports tab and click the globe icon next to port 80. To share the link, right-click the port and set Port Visibility to Public.

Render (free)

Click Deploy on Render, sign in with GitHub and click Deploy Blueprint. The free site sleeps after 15 minutes without visitors.

Your own computer

With Docker installed:

docker build -t imt-event-scheduler .
docker run -p 8080:80 imt-event-scheduler

Then open http://localhost:8080. Setup without Docker is in the README.

Built with

Front end

HTML, CSS and jQuery. The live clash warning uses AJAX.

Back end

PHP 8 on Apache, with prepared statements, hashed passwords and CSRF tokens.

Database

MySQL or MariaDB, with six tables: users, staff IDs, venues, events, attendees and the message log.
